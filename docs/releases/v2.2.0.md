# PII-Shield v2.2.0 Release Notes

PII-Shield v2.2.0 is a minor release focused on detection quality. It fixes twelve confirmed scanner bugs — both under-redaction (leaked secrets) and over-redaction (destroyed log content) — adds an opt-in entity-type label to redaction markers, introduces an instance-based scanner API, and makes startup configuration parsing survive malformed input instead of killing the process. There are no breaking changes.

## Highlights

- Fixed confirmed under-redaction bugs: a quoted email leaking through compact JSON, and `PII_SAFE_REGEX_LIST` being silently ignored for card numbers and URL parameters.
- Fixed confirmed over-redaction bugs: prose being cascade-redacted after a bare word like `password`, URL queries truncated after a second `?`, quote characters invented on unbalanced input, and plain decimal numbers (`6742381.25`) redacted as card candidates.
- New opt-in `PII_ENTITY_TYPE_LABELS`: redaction markers become `[HIDDEN:<type>:<hash>]`, naming the detector that fired (`card`, `key`, `entropy`, …). Off by default; the hash is unchanged, so enabling it does not break tag correlation.
- A malformed `PII_CUSTOM_REGEX_LIST` or `PII_SAFE_REGEX_LIST` no longer terminates the process at startup: the broken rule (or list) is skipped with a `WARNING` and scanning continues.
- New instance-based scanner API for Go embedders; `UpdateConfig` is now safe to call concurrently with scanning.

## Detection Fixes

### Under-redaction (secrets that leaked)

- **Compact-JSON quoted values** (#153): `{"msg":"contact alice@example.com"}` — with no space after the colon — passed the email through unredacted, while the same line with a space redacted correctly. Multi-word quoted values are now re-tokenized on both paths.
- **`PII_SAFE_REGEX_LIST` bypass** (#153): safe-regex whitelist rules were never consulted for Luhn (card) matches or URL query parameters, so a whitelist rule covering those paths was silently ignored.
- **Canonical test cards** (#150): the distinct-digit gate was lowered from 4 to 2, so cards like `4111 1111 1111 1111` (two distinct digits) are detected again while all-same-digit padding is still rejected.
- **Default sensitive keys** (#92): the built-in key list now includes standard cloud credential keys — `aws_access_key_id`, `aws_secret_access_key`, `gcp_credentials`, `slack_token`.

### Over-redaction (log content that was destroyed)

- **Cascade after a bare sensitive word** (#134): `password was rejected for user bob` redacted every word after `password`. Only the immediate next token after a bare sensitive key may now be hidden.
- **URL truncation** (#134): everything after a second `?` in a URL was silently dropped — including secrets that should have been redacted in place. No input bytes are discarded anymore.
- **Quote mangling** (#134): unbalanced quotes (`data="key=value`) caused the scanner to invent quote characters that were not in the input.
- **Decimal false positives** (#158): plain decimal numbers such as `6742381.25` were redacted as card candidates (measured 29% hit rate on full-precision floats in real logs). Digits on both sides of a decimal point now disqualify the run as a card boundary.

### Correctness hardening (#165)

- Strict numeric parsing for `PII_ENTROPY_THRESHOLD`, `PII_CONFIDENCE_THRESHOLD`, and `PII_BIGRAM_DEFAULT_SCORE`: a junk-suffixed value like `9.9junk` was previously applied as `9.9` (silently disabling detection); it is now rejected with a startup `WARNING` and the default is kept.
- Luhn digit collection is ASCII-only, matching the byte arithmetic of the validator — non-ASCII digits no longer feed multibyte offsets into the Luhn math.
- Card boundary checks decode UTF-8 properly: a card number glued to a Cyrillic word (`карта4539…`) was falsely accepted because a continuation byte was misread as a non-letter.
- The token recursion is depth-bounded: a 2 MB `a=a=a=…` line previously took 53.5 s and 779 MB RSS to process; it now completes in well under a second at ~38 MB, with byte-identical output.

## Startup Robustness

A malformed `PII_CUSTOM_REGEX_LIST` or `PII_SAFE_REGEX_LIST` value was fatal at startup (`log.Fatalf` during config load) — a crash loop in a sidecar, and for a Go host embedding the scanner as a library it died before the host's own `main` ran. Both lists now follow the same policy as `PII_SENSITIVE_KEY_PATTERNS` (#166):

- malformed JSON disables that list with a startup `WARNING`;
- an invalid regex inside valid JSON is skipped per rule, and the remaining rules stay active.

Note the operational implication: a skipped **custom** rule means its matches are no longer force-redacted, and a skipped **safe** rule means its matches lose whitelist protection. Watch startup logs for `WARNING` lines after configuration changes.

## Entity-Type Labels (opt-in)

Set `PII_ENTITY_TYPE_LABELS=true` to change redaction markers from `[HIDDEN:<hash>]` to `[HIDDEN:<type>:<hash>]`, where `<type>` names the detector that fired: `card` (Luhn), `key` (sensitive key), `context` (context keyword), `url` (URL parameter entropy), `regex` (unnamed custom rule), or `entropy` (plain entropy). Named custom rules keep their own name as the label. The hash itself is unchanged, so the same value produces the same hash with the flag on or off (#164). Requested by an external integrator for triaging what kind of data was redacted without seeing the data.

## Scanner API for Go Embedders

The scanner now exposes an instance-based API with immutable configuration snapshots (#141). Configuration is published atomically, which also fixes a data race between `UpdateConfig` and concurrent `ScanAndRedact` calls (#134) — embedders may now reconfigure a live scanner safely.

## Observability

- Opt-in aggregated redaction stats: set `PII_STATS_LOG_INTERVAL` to a Go duration (e.g. `1h`) to log a periodic summary — counts of high-entropy secrets, pattern matches, and card numbers, plus lines and bytes processed (#130).
- The CLI metrics HTTP server got a dedicated mux, timeouts, and graceful shutdown (#118).

## Operator & Helm

- `PiiPolicy` runtime configuration (thresholds, key lists, fail policy) is now propagated to injected sidecars (#112).
- Salt can be referenced from a Kubernetes Secret; scanner configuration precedence is documented (#114).
- Pipe injection mode is explicitly marked **experimental** in docs, CRD, and an admission warning (#111).
- The standalone chart keeps the scanner's full 18-key default list unless `PII_SENSITIVE_KEYS` is explicitly set (#132).

## Security & Toolchain

- Go toolchain 1.26.5; stdlib and dependency govulncheck findings resolved (#154, #155).
- The release workflow now runs blocking unit/race tests, SDK and Helm lint/template gates, image smoke tests, and a full-lint gate (#142–#146).

## Breaking Changes

No breaking changes. No salt, credential, or configuration changes are required. Two default-behavior changes to be aware of: plain decimals are no longer redacted as cards (#158), and invalid regex-list entries are skipped with a warning instead of stopping the process (#166).

## Upgrade Notes

Upgrade Helm deployments by updating the chart repository and installing the `2.2.0` chart versions:

```bash
helm repo update
helm upgrade pii-shield pii-shield/pii-shield --version 2.2.0
helm upgrade pii-shield-operator pii-shield/pii-shield-operator --version 2.2.0
```

SDK consumers:

```bash
npm install @aragossa/pii-shield-wasi@2.2.0   # Node
pip install --upgrade pii-shield-wasi==2.2.0  # Python
```

Anyone parsing redaction markers should note that `[HIDDEN:<type>:<hash>]` only appears if `PII_ENTITY_TYPE_LABELS` is explicitly enabled; default output is unchanged.
