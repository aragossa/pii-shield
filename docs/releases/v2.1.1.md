# PII-Shield v2.1.1 Release Notes

PII-Shield v2.1.1 is a patch release. It fixes silent under-redaction in the WASM SDKs (Node and Python) and restores pipe (FIFO) injection mode, which was unusable since the `--watch-file` agent was introduced in v2.0.0. There are no breaking changes and no configuration changes.

## Highlights

- Fixed silent under-redaction in the Node and Python SDKs: key-based sensitive detection (`password`, `token`, `secret`, `api_key`, …) now works by default.
- Fixed pipe injection mode: the sidecar no longer crash-loops on the injected FIFO.

## Bug Fixes

### SDK redaction: sensitive-key detection was inactive

The WASM SDKs seed the scanner through the `init_config` export. That export built a bare `scanner.Config` with only an entropy threshold, a confidence threshold, and the default salt — it never populated `SensitiveKeys`, and the SDKs do not pass that list themselves. As a result, in **every** Node and Python SDK deployment the key-based sensitive detection (`pass`, `secret`, `token`, `key`, `password`, `passwd`, `api_key`, `apikey`, `access_token`, `client_secret`, `cvv`, `cvc`, `auth`, `sign`) was effectively disabled. Only entropy and Luhn detection ran, so low-entropy secrets in key positions (for example `password=hunter2` or a short `api_key`) were passed through **unredacted, with no error** — the SDK appeared to be working.

`init_config` now seeds from `scanner.DefaultConfig()` (the same defaults used by the agent) and applies only the fields the SDK actually overrides, so a partial override — for example supplying just a salt — no longer wipes `SensitiveKeys` or the entropy threshold. The release also fixes compact JSON (`"key":"value"`) handling so that quoted safe values such as timestamps are evaluated correctly and not mishandled during redaction.

This affects the Node and Python WASM SDKs only. The sidecar/agent and operator deployments already seeded the full default config and were never affected.

### Pipe injection mode crash-looped on the FIFO

In `pipe` injection mode the operator injects a named pipe (FIFO) and runs the agent with `--watch-file`. The agent followed the path with `tail`, which targets regular growing files: on a FIFO its line channel closes as soon as it hits EOF on the empty pipe, so the sidecar exited (exit 0) before any writer connected and was restarted into `CrashLoopBackOff`. Because the sidecar is injected as a native sidecar, the pod never reached `Ready`.

The agent now detects a named pipe and reads it directly: a blocking `open(O_RDONLY)` keeps the sidecar running until a writer connects (so the pod becomes `Ready`), lines are sanitized as they arrive, and the pipe is reopened after each EOF to serve subsequent writers. Regular-file injection (`injectionMode: file`) is unchanged and still uses `tail`.

This affects only `injectionMode: pipe`. Deployments using `file` or `ebpf` modes are unaffected.

## Breaking Changes

No breaking changes. No salt, credential, or configuration changes are required by this release.

## Upgrade Notes

Upgrade Helm deployments by updating the chart repository and installing the `2.1.1` chart versions.

```bash
helm repo update
helm upgrade pii-shield pii-shield/pii-shield --version 2.1.1
helm upgrade pii-shield-operator pii-shield/pii-shield-operator --version 2.1.1
```

Existing pods in `pipe` mode must be recreated to pick up the fixed agent image.

SDK consumers should upgrade to the `2.1.1` package to pick up the redaction fix:

```bash
npm install @aragossa/pii-shield-wasi@2.1.1   # Node
pip install --upgrade pii-shield-wasi==2.1.1  # Python
```

Anyone who has been relying on the Node or Python SDK should treat this as a priority upgrade: prior versions may have emitted secrets that were expected to be redacted.
