# PII-Shield v2.1.0 Release Notes

PII-Shield v2.1.0 is a production-hardening release. It keeps the v2.x deployment model stable while adding stronger runtime controls, Kubernetes operations guidance, and supply-chain security improvements.

## Highlights

- Added configurable minimum secret length through `PII_MIN_SECRET_LENGTH`.
- Added optional strong salt enforcement through `PII_REQUIRE_STRONG_SALT`.
- Exposed sidecar fail policy in Helm through `piiConfig.failPolicy`.
- Added optional PrometheusRule alerts for the sidecar and operator charts.
- Added optional operator PodDisruptionBudget support.
- Added configurable webhook `failurePolicy` for operator deployments.
- Added production adoption docs, Kubernetes compatibility guidance, runtime failure-mode guidance, and operational runbooks.
- Hardened supply-chain readiness with CodeQL, Scorecard workflow coverage, pinned GitHub Actions, dependency updates, and release provenance preparation.

## Security

- Remediated known Go vulnerability findings detected by OpenSSF Scorecard and GitHub security scanning.
- Added `PII_REQUIRE_STRONG_SALT` so operators can reject explicitly configured salts shorter than 16 bytes.
- Added release verification documentation for checksums, container image identity, SBOM/provenance, and GitHub artifact attestations.
- Improved security policy and OpenSSF Best Practices evidence.

No salt or credential rotation is required by this release. If `PII_REQUIRE_STRONG_SALT` is enabled, verify that the configured `PII_SALT` is at least 16 bytes before rollout.

## Breaking Changes

No breaking changes are expected.

The new strict controls are opt-in. Default chart values preserve the existing v2.0.5 behavior:

- `piiConfig.requireStrongSalt: "false"`
- `piiConfig.failPolicy: "open"`
- `webhook.failurePolicy: Ignore`
- PrometheusRule alerts disabled
- operator PodDisruptionBudget disabled

## Upgrade Notes

Upgrade Helm deployments by updating the chart repository and installing the `2.1.0` chart versions.

```bash
helm repo update
helm upgrade pii-shield pii-shield/pii-shield --version 2.1.0
helm upgrade pii-shield-operator pii-shield/pii-shield-operator --version 2.1.0
```

For production environments:

- set a stable `PII_SALT`;
- consider enabling `PII_REQUIRE_STRONG_SALT` after validating salt length;
- review `PII_MIN_SECRET_LENGTH` for expected false-positive and false-negative behavior;
- review `piiConfig.failPolicy` before changing fail-open or fail-closed behavior;
- enable PrometheusRule alerts only when Prometheus Operator is installed;
- enable the operator PodDisruptionBudget only when the cluster has enough replicas and scheduling capacity.

Rollback to v2.0.5 should be safe because no CRD schema migration is required by this release. Disable newly enabled strict settings before rollback if they are not supported by the older deployment manifest.

## Known Limitations

- Fully transparent Kubernetes stdout/stderr interception is still not production-complete.
- The operator remains in stabilization phase for enterprise-grade HA, rollback, and admission-webhook policy matrices.
- eBPF interception, Proxy-Wasm gateway integration, and Control Plane UI remain planned or experimental work.
- Signed release and provenance Scorecard improvements require this release to be published successfully and then re-scored.

See `KNOWN_LIMITATIONS.md` and `docs/release-verification.md` for current production-hardening boundaries.

- Helm chart releases exist for both charts at `2.1.0`;
- npm and PyPI packages are published at `2.1.0`;
- GitHub artifact attestations are present for release artifacts;
- container image SBOM/provenance metadata is present where supported by the registry tooling.
